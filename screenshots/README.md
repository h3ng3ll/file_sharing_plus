# Marketing screenshots

Deterministic App Store / marketing screenshots, generated by the on-device
screenshot harness in `integration_test/` (no live LAN required — every screen is
driven by seeded fake BLoC state from `integration_test/fixtures/`).

```
screenshots/
├── macos/   # server UI, 2240×1520 (1120×760 @2×)
└── ios/     # client UI, iPhone 16 Pro Max (1320×2868)
```

## Regenerate

### iOS (client)

Boot a 6.7" simulator and drive the harness. PNGs are written straight to
`screenshots/ios/` by the test driver.

```sh
xcrun simctl boot "iPhone 16 Pro Max"
flutter drive \
  --driver=test_driver/screenshot_driver.dart \
  --target=integration_test/screenshot_test.dart \
  -d "iPhone 16 Pro Max"
```

### macOS (server)

The `integration_test` plugin has no macOS implementation, so the harness captures
each frame via a `RepaintBoundary` and writes the PNG directly. Because the macOS
app is sandboxed, the files land inside the app container and must be copied out:

```sh
flutter drive \
  --driver=test_driver/screenshot_driver.dart \
  --target=integration_test/screenshot_test.dart \
  -d macos

cp ~/Library/Containers/com.example.fileSharing/Data/screenshots/macos/*.png \
   screenshots/macos/
```

When run on macOS the iOS group is skipped (and vice-versa) — the harness picks the
screen set by `Platform.isMacOS`.

## Adding / changing a shot

- Edit the fake state in `integration_test/fixtures/marketing_data.dart`.
- Add a `testWidgets(...)` entry in `integration_test/screenshot_test.dart` (gate it
  with `skip: !Platform.isMacOS` for server screens or `skip: Platform.isMacOS` for
  client screens). The screenshot name's `server-` / `client-` prefix routes it to
  the right platform folder.
